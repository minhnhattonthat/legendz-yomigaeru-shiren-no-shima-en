# Debug tool: how warping works

Command in `AGENTS.md`. Files: `tools/debug/warp.lua`, `scenes.lua`, `virtual_doll.lua`. Regenerate shots and states: `python -X utf8 tools/debug/regen.py`.

## Mechanism (verified: first warp `work/qa/w1`, Small Cave at frame ~900)

The whole game is scripted on the VM (`docs/re/script.md`): each room is one script, entered by `00F2 <ptr>` (change scene), with the entrance number in `0x03006270`.

1. From a cold boot `warp.lua` presses Start while `0x0203BD98` (main mode) is `0x11`, the title screen. It tests RAM, never a frame count.
2. When the mode reads `0x0B`, the title menu, it presses Down then A. The menu writes `8` for New Game (`0x080CEB0A`), and the warp errors out on any other value. Task 0 then runs native `0x08092A09` (guess: the new-game init, from where it sits in the flow). Don't poke the `8`: that skips the menu's cleanup and the title's ribbon sprite stays on screen for the whole run.
3. New game's first `00F2` targets `0x0802483A`. A hook at `0x0808B8B8`, right after the handler stores the pointer in the task PC, swaps in the scene's script and entrance and applies its flags and RAM writes.

Nothing else is patched, so the scene plays as the game plays it, and `F2`'s own flag resets run.

## Partner

A warp with `partner = true` copies the writes the real Reborn made (`tools/debug/partner.lua`, generated by `capture_partner.py` from two RAM dumps, doll byte `0x2C`) and sets flag `0x15F`. Scenes in the cave leave it off, so the doll path itself can be tested. Verified: battles run with this partner to a win (`battle_result`) and a loss (`boss_fight`).

## Scene options that need explaining

- **`free = true`:** clears flags 0, 9, 6, 8 once the keys start. The top loop opens the field menu on Start only with flags 0 and 9 clear (`0x240`: `0014` tests the key, `00DA` tests the flags), rooms clear flag 0 only after their setup (Small Cave: `0x023D7C`), and a warped room doesn't get there. Save refuses (buzzer) with flag 6 or 8 set (`0x080A69F8`).
- **`jump = {line, frames}`:** enter a room, then move the room's task (PC at `0x03002780+0x98+4`) to a line deep in its script, so the map and actors are drawn behind it. Without a room behind it a cutscene plays on black, and a battle's win returns to a gold garbage layer (`battle_first`, after the battle).
- **`mem`:** RAM writes at warp time. `BAG` in `scenes.lua` seeds the bag: id byte + count byte, `0x02036B18` tools (0x3B slots), `0x02036B94` the second tab (0x40 slots, id = item - `0x3E8`), from `0x080D9588`.
- **`save`, `sav`:** `menu_save` really writes the battery. All runs on one ROM name share `tools/mesen/Saves/<rom>.sav`, so `regen.py` runs that scene alone, moves the file to `work/saves/` and boots `continue_save`, `new_game_overwrite` from it.

## Leftover debug menu (phase 7 review)

`SAKURAI DEBUG MENU`: `0x080BC148` starts its task (`0x080BC17C`, priority `0x15`, id at `0x0201C1A8`); nothing in the ROM calls it. Its state table is at `0x0BC198`; state `0x15` reads the keys, cursor at `0x03000070` (mod 14), A sets state `0x1E + cursor`. Items, ASCII at `0x44D134` (stride `0x19`): bouken no kiroku, houmon no kiroku, waza no syuutoku, tatakai no kiroku (battle record, `0x0BF3E0`), doll syousai, waza list, waza kumikae, soul doll, waza tukau, save test, load test, backup erase, connect test, waza copy. Its menu text is a debug font that doesn't show; the pages draw on BG2 at the field camera's scroll, so read them from a VRAM dump (`ppudump.lua`, then `tiles.py map ... --map-at 0xf000 --tiles-at 0 --fmt gba4`).

Scene option `run = {frames, RAM, hex}` writes VM bytecode to unused RAM (`0x0203FF00`, asserted zero) and points the room's task there: `0019 0x080BC149` (native call), then a wait loop. `debug_battle_record` uses it. Other items: change the Down count.

## Known limits

- **What `REACHED` proves:** the warp fired. It doesn't prove the room is right; read `work/qa/scenes/proof*.png`. A room entered this way shows no story state: flags are unset unless the scene lists them, so people and events may differ from a real playthrough.
- **A save in `tools/mesen/Saves/` breaks warps run by hand:** New Game asks to overwrite, the first `00F2` never comes, no `REACHED`. `regen.py` moves it aside; by hand, delete it.
- **`story_*` scenes jump to lines:** the room's own setup for that beat doesn't run, so actors can be missing and a chapter's card or intro isn't played. Enough to read its text; a chapter proof with its real entry needs flags from each room's `000B` tests. Not done.
- **Not reached:** random encounters (walking in Blue Cave for 1,400 frames with `free` gave none; whether the player moved wasn't checked); which rooms hold them. Auto-adventure past its intro; card mode past its reel game.
